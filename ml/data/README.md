# Dataset — seed set (Phase 1 start)

`seed.jsonl` is the **seed** for the FYP dataset: 60 hand-written examples,
6 per scenario, in the plan's JSONL format (plan §10.1). It is the
starting point, not the training set — the plan targets 1,500–4,000
reviewed examples before any fine-tuning result is claimed.

## Format (one JSON object per line)

```json
{
  "scenario": "late_payment",
  "context": {"relationship": "regular_client", "imposition": "high"},
  "input": "Client has not paid invoice #1048, now 12 days overdue. ...",
  "strategy": "negative_politeness",
  "reply": "Hi, I hope your week is going well. ...",
  "explanation": "Hedged request plus an offer of help ...",
  "tone": "polite"
}
```

| Field | Values |
|---|---|
| `scenario` | One of the 10 plan scenarios: `late_payment`, `deadline_extension`, `scope_creep`, `revision_limit`, `low-budget_offer`, `ghosting_follow_up`, `rude_client`, `refund_demand`, `boundary_setting`, `compliment_negotiation`. (Slug spelling matches `apps/api/app/services/llm_client.py`.) |
| `context.relationship` | `new_client` \| `regular_client` \| `long_term_client` |
| `context.imposition` | `low` \| `medium` \| `high` (Brown & Levinson W = Distance + Power + Imposition) |
| `strategy` | `bald_on_record` \| `positive_politeness` \| `negative_politeness` \| `off_record` \| `avoidance` |
| `tone` | `polite` \| `friendly` \| `firm` \| `formal` |
| `input` / `reply` / `explanation` | Free text, English only for this version. |

## Split (80/10/10)

Split **by scenario** (stratified) so every scenario appears in every
split, with a fixed seed for reproducibility:

```bash
python -m ml.evaluation.metrics --split --seed 42   # writes ml/data/splits/
# train.jsonl 40 · val.jsonl 10 · test.jsonl 10  (4/1/1 per scenario from the 60 seeds)
```

The **test split is never used in training** — not for fitting, not for
prompt selection, not for checkpoint choice. When the dataset grows, the
same script re-splits the full file.

## Labeling notes

- **Two annotators + linguist** (plan §10.1): every example added after
  the seed needs a second annotator's strategy label; disagreements go
  to the linguistics supervisor. Target Cohen's kappa ≥ 0.7 before the
  dataset is called "labelled".
- **No real data.** No real names, emails, phone numbers, invoice
  numbers from real clients, or pasted real conversations. Invoice
  numbers and amounts in the seed (`#1048`, `$50`) are fictional.
  Synthetic examples generated by a large LLM must pass linguist review
  before they count.
- **Quality > quantity.** A wrong-strategy example teaches the model
  the wrong mapping; delete a doubtful example rather than keep it.
- **Dedupe.** Same input wording with a different label is a labeling
  error — fix the label, don't keep both.
- **Known imbalance (seed only):** `negative_politeness` is 34/60 —
  most freelancer asks are high-imposition, so the seed skews that way.
  When growing the set, deliberately add `bald_on_record`,
  `positive_politeness` and `off_record` examples (low-imposition and
  criticism cases) until no strategy is below ~15% of the set.
- **Toxic / biased samples:** filter out any example that is abusive,
  threatening, deceptive, or that stereotypes a protected group.

## Growing the set (Phase 3)

1. Write new examples in the same format (team-written first).
2. Optional: draft with a large LLM, then **linguist review** — never
   bulk-accept synthetic output.
3. Re-run the split + `ml/evaluation/metrics.py` to confirm the new
   examples don't break the baselines.
4. Record the dataset version in `CHANGELOG.md` (e.g. `dataset-v0.2`).
