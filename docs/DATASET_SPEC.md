# Dataset Specification

## 1. Goal
1,500 to 4,000 high-quality instruction examples of freelancer-client situations with theory-guided replies. Quality over quantity.

## 2. Scenario taxonomy (to be finalized with linguists)
late_payment, deadline_extension, scope_creep, revision_limit, low_budget_offer, ghosting_followup, rude_client, refund_demand, boundary_setting, negotiation, thanks_and_closing.

## 3. Record format (JSONL, one per line)
```json
{
  "id": "ex_0001",
  "scenario": "late_payment",
  "context": {"relationship": "regular_client", "imposition": "high", "power": "client_higher"},
  "input": "Invoice is 12 days overdue. I want my money.",
  "strategy": "negative_politeness",
  "tone": "polite",
  "reply": "Hi Sam, I hope your week is going well. I'm following up on invoice #12, which was due on the 3rd. Could you let me know when I can expect payment? Happy to resend it if helpful.",
  "explanation": "Hedged request and offer of help reduce imposition while keeping the deadline clear.",
  "source": "human|synthetic_reviewed",
  "annotator_ids": ["a1", "a2"],
  "linguist_reviewed": true
}
```

## 4. Strategy labels
`bald_on_record`, `positive_politeness`, `negative_politeness`, `off_record`.

## 5. Annotation guidelines
- Two annotators label strategy independently; linguist resolves disagreements.
- Target Cohen's kappa >= 0.7.
- Replies must be professional, concise (40-120 words), no manipulation, threats or false claims.
- Do not invent amounts, dates or names not given in the input.

## 6. Sources
1. Team-written examples.
2. Synthetic examples generated by a larger LLM, then linguist-reviewed (mark `source`).
3. Anonymized, consented real-style conversations only.

## 7. Privacy and hygiene
No real names, emails, phone numbers, account numbers or confidential content. Deduplicate. Remove toxic or biased samples. Keep raw data out of git (`ml/data/raw` is ignored).

## 8. Splits
80/10/10 train/validation/test, stratified by scenario and strategy. Test set frozen and hash-recorded.

## 9. Documentation
Maintain a datasheet: purpose, composition, collection process, known limitations, version history.
